Lesson 0004 · 30 minutes

Read a server stream safely

A server-streaming RPC begins like a unary call, then returns a stream. Each received message is ordered. The terminal read tells you whether the stream ended normally or failed.

Lesson 0003 · official Go tutorial · client card

Change the contract

Add this RPC to GreeterService:

rpc GreetMany(GreetRequest) returns (stream GreetResponse);

Run just generate. The generated client method will return a stream client instead of a *GreetResponse.

The client state machine

stream, err := client.GreetMany(ctx, request)
                  │
                  ▼
              Recv() ── message ──► use it, then Recv again
                  │
                  ├── io.EOF ─────► normal end of stream
                  │
                  └── other error ► status-coded failure

Do not treat io.EOF as a failure. It says the server completed the sequence normally. A non-EOF error may be a gRPC status error, network failure, deadline, or cancellation.

Server task

Implement GreetMany so it sends three replies. Use the generated server-stream type. Send these messages in order:

Hello Ritesh #1
Hello Ritesh #2
Hello Ritesh #3

Before each send, check stream.Context().Err(). If it is non-nil, return that error. This is the streaming equivalent of observing ctx.Done().

Client task

Call GreetMany with the same deadline and metadata setup you already have. Loop over stream.Recv(). Print every response. Break only on io.EOF; return all other errors.

Predict the result

Server sendsClient callsExpected outcome
Three replies, then returns nilRecv() four timesThree responses, then io.EOF.
Stops after one reply with status.Error(codes.Unavailable, ...)Recv() againThe second receive returns a status-coded error.
Waits beyond the client deadlineRecv() while waitingA deadline error. The stream context is cancelled at the server.
